# CS-305-Portfolio Project (Software Security)
Artemis Financial Practices for Secure Software Report:

Briefly summarize your client, Artemis Financial, and its software requirements. Who was the client? What issue did the company want you to address?

- Artemis Financial is a financial institution in this project that was looking to upgrade their security software to be in accordance with modern standards. Due to the sensitive nature of the financial information the client processes on a regular basis, the company sought to improve the security of their pre-existing software application. The responsibility that I held in this scenario was to identify potential security vulnerabilities and revise the application with the new security protocols in place. The revisions consisted of me implementing cryptographic functionality, secure client/server communications, certificate generation, and overall vulnerability testing. I carried out all implementations in accordance with best modern software security practices as requested. 

What did you do well when you found your client’s software security vulnerabilities? Why is it important to code securely? What value does software security add to a company’s overall well-being?

- It is my belief that I approached the security concerns in a very efficient manner. Instead of relying on any one solution, I tackled it from the top down and implemented measures as needed. After each implementation I conducted testing to ensure the integrity of the application was still intact. Secure coding is an essential practice, but in this case especially. Being that Artemis Financial is a financial institution, they deal in highly sensitive information. Vulnerabilities can cause these sensitive credentials to be leaked or even worse stolen. This may lead to catastrophic results depending on the extent of damage. Maintaining secure software consistently throughout the entire development life cycle is a necessary measure to ensure that problems are found and remedied as they come. This is an excellent practice to ensure that applications are tested and made with security in mind from the very beginning. Not to mention that secure software builds a bond between client and customer further improving reputation.  

Which part of the vulnerability assessment was challenging or helpful to you?

- One of the more challenging areas of the project was working with the OWASP Dependency Check. The application itself utilized numerous third-party dependencies that had several known vulnerabilities. Being able to learn, properly configure, and run the Dependency check was challenging but incredibly essential to implementing proper security measures. This demonstrated how software itself can contain various concerns through third party dependencies even if the code itself seems to be inherently developed with secure practices in mind.

How did you increase layers of security? In the future, what would you use to assess vulnerabilities and decide which mitigation techniques to use?

- I was able to increase the security of the program overall through implementation of the SHA-256 hash which was used for checksum generation. The proper HTTPS configuration and certificate generation allowed for better security during data transmission. The static vulnerability testing that was made possible with the OWASP Dependency Check allowed for swift navigation of dependencies requiring review. Each of these measures layered the overall security which established a more standardized system by today's standards. Regarding the future, I would continue to utilize tools such as the dependency check alongside standardized manual code review being as proper implementation and vulnerability assessment can make or break a program. I would prefer to tackle mitigation strategy in a linear process of rating severity for each vulnerability, assessing the affected components, and then weighing the potential impact. There is no one solution to fix all issues, however a proper chain of action can be established. Possible mitigation may consist of updating vulnerable dependencies to patched versions, modifying improper code, enforcing proper access control, or even changing configuration of an application. 

How did you make certain the code and software application were functional and secure? After refactoring the code, how did you check to see whether you introduced new vulnerabilities?

- After "refactoring" the code, I performed testing to ensure that functionality remained intact. To follow testing of functionality, I moved on to security testing. Running the application and ensuring its quality was seemingly straight forward. If errors arose, I would manually review refactored sections of the code and reevaluate the implementation process. After the code itself was verified for integrity I was able to test and witness that the SHA-256 checksum produced the anticipated result. After this I configured the application to communicate through HTTPS on a local port and confirmed connection through the browser. To follow this up I performed an additional OWASP Dependency Check to identify known vulnerabilities present in the dependencies found in the project. I was able to implement native Java cryptographic functionality without sourcing anything additional from a third party. I of course manually reviewed the code throughout the process but as I wrapped up with implementation and testing, I conducted a manual review strictly for quality assurance. This was to ensure that the refactored code allowed the program to still run without any negative changes to its functionality.

What resources, tools, or coding practices did you use that might be helpful in future assignments or tasks?

- Throughout the course of this project, I utilized many tools and methods, many of them being new to me. Some of them were Java Keytool which was used for certificate generation. OWASP Dependency Check which provided the means to locate vulnerabilities present in project dependencies. The Java MessageDigest function which was used to implement the SHA-256 hash and of course Maven was used for the overall dependency and project management. Each one of these serving an entirely different function reinforced the importance of proper security measures and taught me a lot about what the industry expects. Tools such as those listed are standardized by today's expectations and security needs to scale with client needs.
